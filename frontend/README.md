# Как устроен frontend

React обновляет интерфейс при изменении состояния. Компонент — функция, возвращающая JSX, похожий на HTML. `props` — данные и обработчики, которые родитель передаёт компоненту. `useState` хранит значение между перерисовками, `useEffect` выполняет действие при изменении зависимостей и может вернуть функцию очистки. TypeScript проверяет типы во время разработки; браузер запускает собранный JavaScript.

Начни чтение с `src/main.tsx`, затем `src/App.tsx`, `src/types.ts`, `src/api/client.ts`, `src/hooks/useSession.ts`. После этого читай компоненты по нужному экрану. Комментарии оставлены у вызовов API и важных решений: сервер как источник состояния, жизненный цикл WebSocket, работа с черновиками и модельным временем. Места создания кнопок отмечены короткими комментариями «Рисуем кнопку …».

Физика, назначения лифтов, проверка прав и статистика выполняются на Go backend. React хранит черновики форм и показывает полученные снимки. `position` в API измеряется в метрах; схема делит значение на высоту этажа и переводит в пиксели. WebSocket даёт полные снимки, при обрыве хук переподключается и делает резервное REST-чтение.

## package.json

JSON не допускает комментарии внутри файла, поэтому пояснения отдельно:

| Поле | Назначение |
|---|---|
| `private` | Защищает от случайной публикации в npm |
| `type: module` | Использует `import` / `export` |
| `scripts.dev` | Запускает Vite для разработки |
| `scripts.build` | Проверяет TypeScript и собирает статические файлы |
| `scripts.preview` | Показывает собранный frontend, без серверного API |
| `scripts.test` | Запускает проверки Vitest |
| `dependencies` | React, React DOM и обработчик YAML |
| `devDependencies` | Компилятор, сборщик, типы и тестовый инструмент |

`package-lock.json` автоматически фиксирует версии зависимостей. Его не редактируют вручную.

## tsconfig.json

| Настройка | Назначение |
|---|---|
| `target: ES2022` | Поддерживаемая версия JavaScript |
| `lib` | Типы языка, DOM и браузерных коллекций |
| `module: ESNext` | Современные модули |
| `moduleResolution: Bundler` | Разрешение импортов для Vite |
| `jsx: react-jsx` | Преобразование JSX в вызовы React |
| `strict` | Строгая проверка типов и null |
| `noUnusedLocals`, `noUnusedParameters` | Находит неиспользуемые переменные |
| `noEmit` | TypeScript проверяет типы, сборку выполняет Vite |
| `verbatimModuleSyntax` | Отличает импорты типов от исполняемого кода |
| `include` | Какие исходные файлы проверять |

Данные для API описаны в `types.ts`. TypeScript не проверяет содержимое сетевого JSON во время выполнения; backend отвечает за валидность модели. YAML черновика сначала проверяется в `lib/config.ts`, затем строго валидируется backend при применении.
